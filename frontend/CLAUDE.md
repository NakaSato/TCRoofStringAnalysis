# frontend/CLAUDE.md

React 19 + Vite 6 + TypeScript (strict) + Tailwind v4 + react-router 7. Run commands from `frontend/`.

## Commands

The package manager is **Bun** (`bun.lock`). Don't use npm, yarn or pnpm, and don't commit their lockfiles.

```bash
bun install                 # bun add <pkg> / bun add -d <pkg> for new dependencies
bun run dev     # :5173, proxies /api -> http://127.0.0.1:8000 (start the backend first)
bun run lint    # tsc --noEmit — type check only, there is no ESLint
bun run build   # tsc -b && vite build
bunx <tool>     # instead of npx
```

Run `bun run lint` and `bun run build` after every change. The Docker build (`Dockerfile`) uses `oven/bun` with `bun install --frozen-lockfile`.

## Structure

- **`src/api/client.ts`**: the only REST client. Response / request types live in `src/api/types/` by area (`auth`, `legacy`, `growatt`, `weather`, `sensors`, `systemLogs`) and are re-exported from `client.ts`, so import them from `../api/client` as before; add a new type to the file of its area.
  - It defines `apiFetch` and the `api.*` methods, with all response types next to them.
  - Base URL is `VITE_API_BASE_URL` (default `/api`). The JWT is kept in localStorage.
  - New endpoints get a typed method here; don't call `fetch` from components.
- **Routes** (`App.tsx`, all inside `components/Layout.tsx`). **The plant is in the URL**, never in hidden state:
  - Fleet-wide: `/` (plant directory, `FleetHomePage` → `components/FleetPlantDirectoryPanel.tsx`: state in `fleetDirectory/useFleetDirectory`, sections `HeroBanner`, `PlantFilterBar`, `PlantTable` (Plant Image = an Esri World Imagery satellite view of the roof from the plant's coordinates, `PlantThumbnail` in `parts.tsx`; the drawn panel when a plant has no location or the image fails), `SelectedPlantStrip`, `PlantPager`, each taking the hook result as `d`), `/map` (Plant Map, `PlantMapPage`: every visible plant on a Leaflet map (Esri satellite + labels, or CARTO dark via `base=dark`), marker colour = live status, size = DC kWp; plants at 0,0 / no coordinates are listed as "no location", never placed; URL `status`, `q`, `base`, `plant`; uses the fleet list + live poll only), `/growatt`, `/alarms`, `/sensors` (Weather Sensors, not in the sidebar: reached from Active Alarm sensor rows; listed in `HIDDEN_NAV` in `Layout.tsx` for the header title. `?tab=status|info`, `sensor`, `status` (incl. `low` = data gaps, `flags` = health flags), `phase`, `q`, `sort`, `desc`; page-local DB list re-read every 5 min, overlaid by `key` with the live status from `useLivePoll(api.getLiveSensorStatus)`; header shows "Status checked N / M" until the backend sweep is complete, then "Live · hh:mm"; health flags = DB `flags` + live `flags` (`stale_history`), shown as chips with the reason as tooltip; the Info tab polls `api.getLiveSensor` for the open sensor (live state, newest reading, next-refresh countdown, admin-only raw record) and charts today's stored series via `getGrowattPlantWeather(…, sensor)`; no context), `/she`, `/settings`, `/users`, `/logs` (System → Logs, admin only: `api.listSystemLogs` / `api.getSystemLogSummary`; filters in the URL `level`, `source`, `job`, `range` (1h/24h/7d/14d), `run`, `q` (debounced 300 ms); polls `after_id` every 15 s while visible and on the newest page, "Load older" pages with `before_id` and pauses polling; row click expands message + traceback with Copy; a run chip filters to that run).
  - One plant: `/plant/:plantId` (overview), `/plant/:plantId/{generation,inverters,sensors,strings,string,string-layout,maintenance}`. `string` is one string in depth (`pages/StringDetailPage.tsx`, `?sn=&no=`, not in the tab bar; String Diagnostics stays highlighted): figures, I-V / P-V, profile vs. peers (current, power, voltage), current mismatch per 5-min slot and by hour of day (only slots where the peers carry ≥ 1 A; reference lines = the live string check's −15 % / −40 %), daily energy for a range, the inverter's strings (overview day), stored records (paged, CSV). The String Inspector (a centered modal, full screen on phones) has "Open full analysis", which opens it with the same period. Both use `components/stringDetail/`: `period.ts` (one day, a range ≤ 31 days and/or a time-of-day window), `StringPeriodPicker` (‹ date › opens a modal `Dialog` with one range calendar: a day or first → last day, presets, Cancel / Apply; clock popover), `useStringDetail` (`api.getGrowattStringDetail(…, { day, endDay, start, end })`), `analysis.ts` (measured mismatch specs). For any period other than the overview's whole day, the figures come from the detail (vs. the peer mean) and the overview's diagnosis / health are shown as "for <day> only". `sensors` is `PlantSensorsPage` (`pages/SensorsPage.tsx` holds only the two page exports; the code is in `pages/sensors/`: `SensorsView` list, `PlantSensorView` stored-day card, `SensorInfo`, `dayChart` (`sensorDaySpec`, `usePlantPower`), `useSensorDetail`, `useSensorDayChart` (stored day + today's not-yet-stored records → chart spec; shared with the Plant Overview), `format`): the Weather Sensors Status / Info views for that plant only (`listSensors(plantId)` / `getLiveSensorStatus(plantId)` send `?plant_id=`, so the live sweep checks only its dataloggers; the plant column and phase filter are hidden). Layout (shadcn, Active Alarm style): no title row; line `Tabs` when the plant has several sensors; the stored-day `Card` (`#weather-station`; Popover + Calendar day picker, `?day=`, time-of-day window `?from=&to=` (sent as `start`/`end`; numbers and chart cover only it, no live tail, no PR), CSV, day numbers incl. avg ambient, peak irradiance including the live tail, plus IEC 61724 PR from the plant overview for the overview's whole day, chart, `Empty`); at the bottom one sensor `Card` (id + status badge, Refresh, an `Alert` saying why and what to check when it isn't online, health flags, the device table: datalogger, address, name, phase, lost, listed, last upload, status rule; admin raw record in a `Collapsible`). Today's chart there appends the records newer than the last stored slot: today's `env_data` records from `api.getLiveSensorToday` (polled on `refresh_in_s`, today only, backend memory only) plus the polled `env_last_data` readings (component memory, ≤ 24 points); the DB wins for every slot it holds; shaded "Live, not stored yet". Both sensor charts come from `sensorDaySpec`: x at least 05:00–19:00 (or the window), irradiance axis ≥ 1,200 W/m², humidity 0–100 %, wind direction N/E/S/W, record gaps hatched, today's "Now" line; the day card adds the plant's stored AC power (overview `timeseries`, today from context, other days `getGrowattPlantOverview(id, day)` once per tab; amber dots = producing slots summed over fewer inverters than usual, from the slot's `inverters`; the tooltip also says how many are `held` from their reading ≤ 10 min before), legend toggles and drag-to-zoom (writes `?from=&to=`). Plant Overview's Weather card shows each sensor's newest reading as reported: live (`useLivePoll(api.getGrowattLiveWeather)`) when at least as new as the stored record, else the stored record ("Last sync"). `PlantRoute` shows "not found" when the backend answers 404 (unknown, or not assigned to an engineer).
  - Old URLs (`/inverters`, …) redirect to the same page of the last plant opened (`localStorage`, guarded), else `/`.
  - Build plant links with `plantPath(id, page)` (`context/routes.ts`) or `usePlantHref()`; switch plant with `selectGrowattPlant(id)`, which keeps the current page.
  - **A page's own choices go in the query string** via `useUrlState()` (`src/lib/useUrlState.ts`): `set({ key: value })` patches several keys at once, drops defaults (null / "" / false) and replaces the history entry. Validate what you read (`pick`, `pickDay`, `pickTime`): URLs are hand-editable. Don't reset such state in an effect on mount (it would wipe the URL); switching plant drops the query by itself. In use: Generation `chart`, `sort`, `desc`; Inverters `sn`, `tab`, `days`, `q`, `show`; Strings `inv`, `status`, `q`, `string`, `sort`, `desc` (table only); String page `sn`, `no`, `day`, `to` (range end), `from_t`, `to_t` (time window); String Layout `filter`; plant Sensors `sensor`, `day`, `from`, `to`; Active Alarm `day`, `q`, `level`, `open`, `plant`, `code`, `src`.
- **`src/context/`**: data is loaded **per route**. `routes.ts` → `routeData(pathname)` is the one place that decides what a route needs; `DataScope` (in `AppContext.tsx`) mounts every provider once and switches each on or off from the URL. A provider that is off fetches and polls nothing.
  - `AuthContext`: user, login/logout. Loads no data.
  - `FleetContext`: plant list (`/growatt/plants`, read once per session) and the live fleet poll (`/growatt/live/plants`, backend memory cache). Both run on every route: the sidebar's Fleet card (plants, online / offline, live AC power, DC capacity) is always shown, and plant pages use the poll for the banner status.
- **Sidebar** (`components/Layout.tsx`): global pages only. On desktop it collapses to an icon strip (`w-16`: logo, fleet LED, nav icons, avatar; names and fleet figures in right-side tooltips) and expands again with the top-bar button (PanelLeft icon, tooltip "Resize left tab bar") or Ctrl/⌘ + B; the choice is kept in `localStorage` (`tcroof.navHidden`, guarded). Mobile uses the slide-in menu. Plant pages are reached through the plant's own tab bar (`SelectedPlantBanner`), not the sidebar.
  - `PlantContext`: the URL plant's DB overview (memory cache per plant, so switching its tabs doesn't refetch; refreshed every 5 min) and `/live/plants/{id}/latest`, polled on every plant page (the banner's string status is judged on it; the backend caches each inverter ≥ 270 s, so page switches add no Growatt calls).
  - `LegacyContext`: old analysis tables (`/plants`, datasets, latest analysis), admin only, on `/she`, `/settings` or plant Maintenance.
  - `useAppContext()` merges them; values of a provider that is off are empty / null. Adding a page: add its route, then its needs in `routeData`.
  - Data loading uses `useEffect` and `setInterval`. `@tanstack/react-query` is installed but **not used**, so don't mix in a second fetching style without migrating the context.
  - Dev only: `window.__apiLog` lists every API request with the route it was made on (check what a page loads).
- **`src/pages/*`**: one page per route.
- **PWA and branding** (`vite-plugin-pwa` in `vite.config.ts`): installable app with `manifest.webmanifest` and a Workbox service worker (`registerType: autoUpdate`). It precaches the static build only; `/api/**` is excluded from the navigation fallback and there is **no runtime caching**, so API calls always hit the network and no live value is stored in the browser. Don't add runtime caching for `/api`. Icons come from the TC Renewable logo (the iOS app's `AppIcon-source.svg`): `public/favicon.svg` (also the brand mark in the sidebar and on the login page), `favicon-32.png`, `apple-touch-icon.png` (180), `icons/icon-192.png`, `icons/icon-512.png` and `icons/maskable-512.png` (logo at 75 % inside the maskable safe zone). Regenerate the PNGs with `rsvg-convert`. `firebase.json` serves `sw.js`, `registerSW.js` and the manifest with `Cache-Control: no-cache` so updates reach users.
- **`src/components/ui.tsx`**: shared app pieces, built on the shadcn primitives below.
  - Components: `PageHeader`, `Panel`, `KpiTile`, `StatusBadge`, `Led`, `Meter`, `EmptyState`, `LoadingState`, `SkeletonRows`, `SkeletonKpis`, `SkeletonChart`.
  - **Loading UI:** `LoadingState` = `Spinner` + label, plus a skeleton of what is coming via `shape` (`lines` / `table` / `chart` / `kpis` / `page`), so the layout doesn't jump. Inline waits use `Spinner` (`@/components/ui/spinner`): a refresh button shows `Spinner` in place of its icon while loading (no spinning `RefreshCw`), a busy button shows it before its label. As in the shadcn docs, an icon or `Spinner` next to a Button/Badge label gets `data-icon="inline-start"` (or `inline-end`) so that side's padding tightens; give `sm`/`xs` buttons a `size-3` spinner (`Spinner`'s own `size-4` overrides the button's icon sizing). Don't hand-roll `animate-spin` circles or bare "Loading…" text.
  - Formatters `fmt` and `fmtInt` return `"—"` for null or non-finite values.
- **`src/components/ui/*`**: shadcn/ui components (Radix, `components.json`, style `radix-nova`), owned source.
  - Use them instead of raw elements: `Button` (variants `default` = solar CTA, `secondary` (default), `outline`, `accent`, `destructive`, `ghost`; sizes `sm`/`xs`/`icon-sm`…), `Input`, `Textarea`, `Label`, `Select`, `Tabs`, `Table` (`containerClassName="table-wrap"` for the scroll-shadow frame), `Badge` (variants `ok`/`warn`/`crit`/`info`/`neutral`), `Card`, `Dialog`, `Tooltip` (provider in `App.tsx`), `Command`, `Skeleton`, `Spinner`.
  - They are restyled to the control-room theme; keep that when adding more (`bunx --bun shadcn@latest add <name>`, then fix any `from "cn"` import to `@/lib/utils` and match the compact `text-xs` sizing).
  - Import with the `@/` alias (`@/components/ui/button`); `cn()` is in `src/lib/utils.ts`.
- **Charts:** D3 only (no Plotly). Every x/y chart is `components/PanelChart.tsx`: pass a `PanelChartSpec` built with `useMemo` (`xKind` time / linear / band, stacked `panels`, each with **one** y scale; never a second y axis, so two units = two panels). Nulls are gaps, never 0. Colours come from `components/chartTheme.ts` by role (`SERIES.ac`, `SERIES.dc`, …; `STATUS.*` only for state); modelled series are labelled "(modelled)" and drawn dashed/dotted in `SERIES.reference`. Optional extras: `xDomain` (x range shown at least), `xStep` (fixed record interval; default = median step, which a sparse range overestimates), `gaps` (hatch every record gap the lines break at), `bands` / `markers` (shaded x ranges, vertical lines such as "now"), per-panel `ticks` / `tickFormat`; props `legendToggle` (legend items hide / show series) and `onBrush` (mouse drag reports an x range). Special-purpose D3 charts (comparison bars, string heatmap) are in `D3Charts.tsx`; shared tooltip/sizing helpers in `chartKit.tsx`.
- **Styling:**
  - Tailwind v4 design tokens are in `src/index.css` under `@theme`: `ink-*` surfaces, `solar-*` and `energy-*` accents. shadcn's variables (`--background`, `--primary`, `--border`, …) are mapped onto them in `:root`; the app is dark only (`<html class="dark">`).
  - Remaining component classes under `@layer components`: `panel-pad`/`panel-header`, `eyebrow`, `led-*`, `num`, `table-wrap`, `callout-*`. The old `btn`/`input`/`select`/`data-table`/`tabs`/`badge-*` classes were removed; use the shadcn components.
  - The UI is a dark control-room theme.

## Growatt data in the UI

**Live and DB data stay separate; the context combines them.**

| Data | Source | Refresh |
|---|---|---|
| Fleet list | `api.listGrowattPlants()` (DB), overlaid with `api.getGrowattLivePlants()` | list once per session; live when `refresh_in_s` says, on fleet routes and plant pages |
| URL plant overview | `api.getGrowattPlantOverview(id, day?)` (DB) | every 5 min, cached per plant across its tabs |
| URL plant live values | `api.getGrowattLivePlantLatest(id)` | when `refresh_in_s` says, on every plant page |

- **What the overlay changes.** `selectedPlantOverview` is the DB overview with the latest live record applied. Only "current" fields change: `kpis.current_power_kw`, `inverters[].current_ac_kw`, `mppt_latest`, `live_at`, and `strings[].live_voltage_v`/`live_current_a`/`live_power_w`/`live_status`/`live_reason`, plus `live.strings` (live string-check counts). Daily aggregates always come from the DB.
- **Plant directory hero** (`fleetDirectory/HeroBanner`): Plant KPIs and Plant Status are realtime only. Current power / total yield / status come from the fleet poll; Yield today and Revenue today come from `api.getGrowattLivePlantsToday()` (backend sweep of `plant/data`, polled by `useFleetDirectory` on `refresh_in_s` only while the directory is open). A plant not checked yet is "—", never the stored day's yield, and the header shows "Checking n/N" until the sweep is complete. Active Alarms: "N faulty now" is live (plant status, click = Faulty filter); the donut is the stored alarm log, labelled "Log · hh:mm" (its last sync). The table's Status column sorts Faulty → Disconnected → Normal (loading last).
- **Plant status in the banner is realtime only:** `Disconnected` from the fleet poll's plant status, else `String Fault` / `String Warning` / `Normal` from `live.strings` (the backend's live string check). The stored-day string classification (`kpis.critical_strings`, `strings[].status`) is a day analysis for the Strings page and is not used for the status.
- **Polling** stops while `document.hidden`. Live values are never stored, in the browser or anywhere else.
- **Fleet alarm log** (Active Alarm page): one DB request, `api.getFleetAlarms(day)` (`/growatt/alarms`), for every plant the user can see; the worker syncs Growatt's alarm log into SQL. `context/alarmLogStore.ts` keeps each day's answer in tab memory (not localStorage) so revisits show it at once, and re-reads it in the background only while the page is visible: today just after the worker's next `alarms` run (`meta.next_run_at` + 45 s, 60 s–15 min; 2 min when the run is overdue or unknown), past days every 30 min. Cleared on logout. `plants[].synced_inverters` / `synced_at` give per-plant coverage: show an unsynced plant as "not synced yet", never as "no alarms". Growatt reports an alarm that is still present again every ~5 min as a separate record with end = start, so `components/alarmEvents.ts` groups records of one inverter + code ≤ 10 min apart (`EVENT_GAP_MIN`) into one event (start → last report); an event is "Open" when, today, its last report is within 10 min of **its inverter's** last read (`alarms[].read_at`; the worker re-reads inverters on different tiers, so never use the plant's oldest read). The sync pill turns amber when today's next `alarms` run is over 20 min overdue (`meta.next_run_at`). The per-plant "Growatt Fault Log" panel (`components/GrowattAlarmLogPanel.tsx`) still uses the live endpoint, but groups its records into events with the same `toEvents` rule (one row per event: level LED + message + code, inverter name linking to `inverters?sn=` when the page passes `inverterNames` / `inverterHref`, first → last report, duration × reports, Open when today's last report is within `EVENT_GAP_MIN` of now; open first, then newest).
- **Weather sensors on Active Alarm** (hook `useSensorAlarms` in `components/SensorAlarmPanel.tsx`, shared pieces in `components/sensorView.tsx`): sensors are rows of the same Alarms table (`sensorEvents`, source "sensor", code badge "Sensor", device links to the Sensors Info view; CSV has a `source` column). For **today**, rows are sensors the live sweep found offline or late plus sensors with a health flag (`api.listSensors(undefined, day)` + `useLivePoll(api.getLiveSensorStatus)`, the same backend sweep as `/sensors`); a sensor not checked yet is never listed as offline; duration = time since the last upload. `stale_history` ("History behind": our stored history is behind, a sync issue) is not a row; it is counted in the Sync badge tooltip. For a **past day**, there is no live state, so rows are stored data gaps (`coverage_pct` < `meta.alarm_coverage_pct`), never open. The "Sensors offline" / "Sensor data gaps" number filters the table to sensors.
- **Active Alarm layout** (shadcn components only, no decorative icons): header with Sync badge (tooltip = coverage) and a Popover + Calendar day picker; one summary Card of numbers; the Alarms Card has line Tabs All / Open, search, Export CSV, then one row of Selects (source `src`, level, plant, code). The table card ends at the bottom of the screen: rows per page are measured to fit (`fit.pageSize`, recomputed on resize), with shadcn `Pagination` under it; the page resets to 1 when the day or a filter changes. Order: open first, faults before warnings, then newest. Event grouping and the hourly chart spec live in `components/alarmEvents.ts`; the "Alarms by hour" chart is on the Sensors Info view (`PlantAlarmsByHour`: today's inverter alarm events of the sensor's plant, via the same `useAlarmLog` store), not on Active Alarm.
- **Inverters page** (`pages/InvertersPage.tsx`, pieces in `pages/inverters/`: `PlantInvertersCard`, `InverterCard`, `DetailTabs`, `shared`): shadcn Cards, no decorative icons. "Now" (live) and "Stored day" are always separate, labelled groups, because the overview's stored day can be older than the live record and the context overlay is then not applied. "Now" values, status, MPPT energy, grid / fault codes and the live string check come from `plantLive` (the raw live record exposed by `PlantContext`), never from the overlay; an inverter missing from the live answer shows "No record", not a spinner. Alerts: stored history behind the live day, live unavailable, inverters with no live record, settings that curtail (off / power limit), non-zero live fault codes, and the stored day's string anomalies / inactive strings. One comparison table (row = select, `?sn=`; filter by name / SN search `?q=` and state `?show=` all | online | not_online | low | issues, where issues = anomalies + inactive strings of the stored day) replaces the old side list, comparison chart and wide table; line tabs Performance / Strings / Grid & faults / History (`?tab=`).
- **Generation page** (`pages/GenerationPrPage.tsx`, pieces in `pages/generation/`: `charts` (chart specs), `InverterTable`): shadcn Cards, no decorative icons, **stored day only** (no live overlay values; live is on Inverters). Alert when the stored day is behind the live day. Figures in two labelled groups, Energy (yield + revenue at the plant tariff, specific yield, peak AC, lifetime) and Performance (PR: IEC 61724 when the sensor gives one, else peer-relative, always labelled, with the backend's reason when IEC is missing; efficiency; inverter temp; insolation); the 5-min power chart (clear-sky envelope modelled, amber dots = slots summed over fewer inverters); "By inverter" chart with line tabs Yield & PR / Temperature (`?chart=`); "Loss breakdown" (modelled badge; a note when the backend built none); Google Weather; a sortable inverter table (`?sort=&desc=`, nulls last) whose rows open `inverters?sn=`.
- **Plant Overview** (`pages/OverviewPage.tsx`, pieces in `pages/overview/`: `WeatherCard`, `SummaryCards`, `IconStat`): no status list or verdict, and **as little text as possible**: secondary figures are `IconStat` tiles (icon + value + unit; the label and any context go in the tooltip and `aria-label`), no card descriptions, card links are icon-only arrow buttons. Right under the tab bar, a strip of five `KpiTile`s (no accent bar): PV Power (live AC sum, % of kWp), Yield and Revenue of the stored day (labelled Today, or the day when it is behind; specific yield, tariff), Inverters Online (live: reporting with status ≠ 0, of `inverter_count`; avg temp), String Health (`avg_health_score` / 100, critical · warning). The top card has no header: three headline numbers (Power now from `plantLive` with the Live · hh:mm / Last sync badge and a thin bar for % of kWp, "night" before 06:00 / from 19:00 plant-local; Energy (≈ ฿ revenue) and PR (target) of the stored day, labelled with that day when it isn't today), the 5-min power chart (`powerSpec` from `generation/charts`) and tiles (DC now, irradiance now if a sensor, peak, specific yield, CO₂). Next to it: Site card (satellite map; capacity, lifetime, tariff tiles) and Weather card (each sensor's newest reading as reported, as tiles; Google rain at 09/12/17 as icon slots, modelled, details in the tooltip). The page polls `getGrowattLiveWeather` once (only when the plant has a sensor) and shares it. Under the top card, in the same left column (so the page has no gap beside Site / Weather), the Inverters (live counts: 1 normal, 0 offline, 3 fault; stored-day efficiency / temperature tiles; badges only for low yield, power-limited, switched off) and String Diagnostics (stored-day health split, no worst-strings list) summary cards, equal height. Then the Growatt Fault Log with `compact`: one "No alarms" line instead of the large empty state, and instead of the table its events grouped by day (Today / Yesterday / date, newest first; open first inside a day), each row = level LED + message + code, inverter link, a bar of first → last report on a 05:00–19:00 axis (dot for a single report, pulse when open), duration × reports or an Open badge; 12 rows, then "Show all N". With one weather sensor, its Live / Last sync time sits in the Weather card title. Above the fault log, when the plant has a sensor, `SensorTodayCard` shows the Sensors tab's today chart (`useSensorDayChart`, always today even if the stored figures are of an older day; line tabs with several sensors; arrow to `sensors#weather-station`).
- **Show freshness:** "Live · hh:mm" when live data is fresh, "Last sync" when it's stale or unavailable.
- **Many numeric fields are `number | null`.**
  - Render them with `fmt()`.
  - Never substitute plausible defaults (`|| 98.1`, `?? 229.8`, `capacity * 0.72` …). Show "—" instead.
  - Don't show data the backend doesn't measure; there's no grid or load meter data.
- **The Growatt API token never reaches the browser.** All Growatt calls go through the backend.
