# backend/CLAUDE.md

Backend-specific guidance. Run all commands from the **repo root**, not from `backend/`.

## Commands

```bash
PYTHONPATH=backend uv run uvicorn app.main:app --reload --port 8000   # API, Swagger at /docs
uv run pytest -q                                                    # all tests (pythonpath: backend, .)
uv run pytest backend/tests/test_growatt_routes.py -v
backend/scripts/test_postgres.sh                                     # all tests on Postgres 16 (Docker / OrbStack; tests/pg_plugin.py: a fresh DB per test engine; args go to pytest)
pyright --pythonpath .venv/bin/python backend/app backend/solar_core # type check

uv run alembic -c backend/alembic.ini upgrade head
uv run alembic -c backend/alembic.ini revision --autogenerate -m "msg"

PYTHONPATH=backend uv run python -m app.worker --list                # schedule + last runs
PYTHONPATH=backend uv run python -m app.worker --once history        # run one job now
PYTHONPATH=backend uv run python -m app.services.growatt_sync --start 2026-11-05 --end 2026-11-11
PYTHONPATH=backend uv run python -m app.services.daily_summary --dry-run
```

**Two dependency files.** `pyproject.toml` at the repo root is for local `uv` and tests. `backend/pyproject.toml` is what the Docker image installs. Add each new dependency to both.

## Layers

- **`solar_core/`**: pure Pandas/NumPy engine with no FastAPI or SQLAlchemy imports.
  - `ingestion.py`: normalization and the inverter-cloud connectors.
  - `analysis.py`: IEC 61724 PR, string KPIs and faults, returning `AnalysisResults`.
  - `om_management.py`: CM work orders, PM schedule, RCA, PQ and SH&E.
  - `charts.py` (Plotly).
  - `growatt/`: `client.py` (the Growatt OpenAPI client, one method per endpoint) and `parsers.py` (records → rows, e.g. `parse_max_records`); both re-exported from `solar_core.growatt`.
  - `storage.py` is legacy and used only by `test_solar_core.py`.
- **`app/`**: FastAPI.
  - Routes are in `api/routes/*` (the Growatt ones in the package `api/routes/growatt/`, one module per area: `live`, `plants` (DB only), `fleet_config`, `rules`, `iv`, `events`, `sync`; shared pieces in `_common.py`), ORM models in the package `db/models/` (`users`, `legacy`, `growatt`, `rules`, `om`, `claims`, `tools`, `kb` (articles and the PDF library), `pwa`, `plant_docs`, `route` (Visit Route offices), `system`; all re-exported from `app.db.models`), request/response schemas in `schemas/api_schemas.py`.
  - Business logic lives in `services/*`. Keep route functions thin: they call a service and translate its exceptions into `HTTPException` (for example, `GrowattNotFound` becomes 404).
  - Every router is mounted twice, at `/api` and at `/`.
  - Auth is JWT (`app/auth.py`) with two roles. **admin**: everything. **engineer**: only the Growatt plants in `user_plant_assignments` (set by an admin via `/users/{id}/plants`).
    - Every `/growatt/…/plants/{plant_id}/…` route depends on `require_plant_read` / `require_plant_write`; an unassigned plant answers **404** (ids are not revealed). Lists (`/growatt/plants`, `/growatt/live/plants`) are filtered with `allowed_plant_ids` (None = admin = all); the live cache stays fleet-wide.
    - Admin only (`require_admin`): `/users`, `/system/logs*`, fleet module PUT, `/growatt/sync/*`, and the legacy routers (`plants`, `datasets`, `analysis`, `maintenance`, `rca`), which use the local `plants` table with no link to Growatt plants.
    - Assignments are read from the DB per request, so changes apply without a new login. Any other stored role (the former `viewer`) becomes `engineer` at startup.

**Analysis pipeline** (`services/solar_service.py`):
1. ORM rows become a DataFrame, and `Plant` + `string_specs` become a `PlantConfig`.
2. `run_pv_string_analysis` runs.
3. Results are stored on `AnalysisRun` as JSON columns.
4. `reconstruct_analysis_results` rebuilds them for charts.

**Ingestion**:
- Every source must end up as the long-format columns in `solar_core.models.CANONICAL_COLUMNS`. `normalize_dataframe()` also accepts wide SCADA input (`PV1_U` / `pv1_u` …).
- `POST /plants/{id}/datasets/{upload|fetch|simulate}` → `store_dataset_from_dataframe` → `execute_and_store_analysis`.
- `fetch` with `simulate_if_unreachable` (default false): only when the provider endpoint can't be reached (`solar_core.ingestion.EndpointUnreachable`) does the route store simulator data instead, as `source_type = "simulated"` labelled "Sandbox simulator (… unreachable)", never under the provider's name. A response that arrives but can't be parsed stays a 400.

- **Project phases = Growatt accounts.** Each of the 4 phases has its own token (`settings.growatt_accounts()` → `{phase: token}`).
  - `fleet` lists every account and tags each plant with `growatt_plants.phase`.
  - `history` / `backfill` sync each phase's inverters with that phase's token. Live calls look up the plant's phase in the DB, and `/growatt/live/plants` merges every account.
  - `phase IS NULL` means not yet tagged; those plants use the first configured account. The worker re-runs `fleet` every 6 h while any plant is untagged. It also re-runs `fleet` every 6 h (`FLEET_RETRY`) while the last fleet run was `partial` / `failed` (an account hit 10012, or the run was abandoned): `fleet` is the only job that registers weather sensors and inverter changes, and its 05:30 slot is missed when a long job (e.g. `backfill`) holds the worker past 08:30.
  - Jobs run the accounts in parallel, one thread and one DB session each (`_per_phase`; `WORKER_PARALLEL_ACCOUNTS=false` runs them one by one). A failing account makes the run `partial`, and the run fails only when every account fails. `detail.phases` holds each phase's result.
- **Don't invent values.** If a measurement is missing, return `None` / `null`, not a typical-looking default. The same goes for things with no data source: leave them out instead of modelling them as if measured. Grid import / export come only from the plant's energy meter, and load is derived (PV AC + grid), never measured. Label modelled values as modelled: the clear-sky `expected_kw`, the I-V curves, and the peer-relative `pr_pct` / `plant_pr_pct` (strings vs. peers, *not* IEC PR). The measured IEC 61724-1 PR is `kpis.iec_pr_pct` (below).
- **Weather sensors** (`device/env/*`, `services/growatt_weather.py`):

When Growatt registered the device, naive as reported (time zone not verified); **not** a commissioning date. API: `growatt_created_at` on every inverter (`inverter_out`).
    - `device/sn_datalog` → `fleet` (`_sync_missing_dataloggers`): the datalogger serial of an inverter `device/list` named none for. Usually no call at all.
    - `new-api/queryDevicesHistoricalData` → `history` (`growatt_sync._sync_today_batched`), only with `WORKER_HISTORY_BATCH_SIZE` > 0 (default 0 = off): today's records of that many inverters per call instead of one `max_data` call each. Same record fields as `max_data` (probe 15 Nov 2026: same 70 records / 952 string rows for one inverter-day; float32 noise in `pac`). Off by default because a call returns each inverter's whole day so far (≈ 0.6 MB per inverter by midday) and its largest serial list is unknown. Job detail: `batch_calls` / `batch_inverters` / `batch_fallback` / `batch_errors`.
    - `new-api/queryHistoricalData` → `history` (`_sync_today_single`): an inverter whose `max_data` call failed (after its retries) is read once through it before it counts as failed (`day_fallback` in the job detail). An answer with `haveNext` is not used (its paging was not probed).
    - Both of those go through `_store_today`: the answer is stored only when proven complete, i.e. the inverter's newest stored record is from today and the answer reaches back to it; only rows inside the 30-min overlap are written. Otherwise nothing is written and the old path decides.
    - `device/max/max_last_data`, then `new-api/queryLastData` → `/live/plants/{id}/latest` (`growatt_live._newest_records`): when `max_data` refuses an inverter (10012 inside its 4–5 min window, or any Growatt error), its newest record alone comes from these. Each inverter row carries `record_source` (`max_data` / `max_last_data` / `queryLastData`); a fallback row has no `previous_strings` (the live string check cannot confirm persistence, so it downgrades as designed), `interval_s` null and a one-point `power` tail. A record of another day = no record today. If they refuse too, the `max_data` error stands.
    - Not merged, because nothing in the app is missing what they give: `plant/sn_plant` (the plant of a serial: the registry has it), `device/check/sn` (confirms a datalogger serial; its model is already in `device/datalogger/list`), `user/c_user_list` (the Growatt account's users). `readMaxParam`, `new-api/getWiFiSignalByDevice` and `new-api/queryDfcData` answered an error / no data on every account and were dropped from the probe script.
  - `/live/plants/{id}/latest` also returns, from the newest `max_data` record:
    - `grid`: phase/line V, A, `pf`, `reactPower`.
    - `diagnostics`: `faultType`, `faultCode1/2`, `warnCode1`, `warningValue1-3`, `pidFaultCode` and `StrBreak`; `pvIso`, where 65530 = no reading → null; `temperature` / `temperature2` / `temperature3` = AMTemp1 / INVTemp / BTTemp of Growatt's history export (checked on one inverter, 13 Nov 2026; `temperature5` = AMTemp2; the stored `temperature_c` is AMTemp1, and the API keys `ipm_temperature_c` / `boost_temperature_c` keep their old names); `afciStatus` and `afciPv1/2`; `gfci`; `r/s/tDci`; `timeTotal` in seconds → `time_total_h`.
    - `mppt_energy`: `epv{n}Today/Total`, kWh.
    These are live only and never stored. Units of GFCI/DCI/AFCI are Growatt's own and are shown as reported.
- **Compact JSON:** every JSON column is written without spaces (`session._compact_json`), and `growatt_inverter_readings.mppt_json` is stored as `[[n, v, i, p], …]` (`CompactMppt`), read back as `[{"mppt", "v", "i", "p"}]`; rows in the old dict form read unchanged (Nov 2026: the key names were over half of a reading).
- **Timestamps:**
  - Growatt reading tables are naive plant-local (Bangkok) time.
  - App bookkeeping columns (`sync_runs`, `published_docs`, `synced_at`) are UTC. SQLite drops tzinfo, so store UTC and read naive values back as UTC (`jobs._aware`).
- **SQL must run on SQLite and Postgres.** Use SQLAlchemy expressions; no `strftime` / `date()` in raw `text()`. Time bucketing happens in Python.

## Logging (System → Logs)

- **Use `logging.getLogger(__name__)`; never `basicConfig`.** `app/logging_db.setup_logging(source)` sets up the console and `DbLogHandler` (`source` = `api` from `main.py`'s lifespan, `worker` from `worker.py`, `cli` from the CLI entry points). Records at `LOG_DB_LEVEL` and above go to SQL `app_logs`; `sqlalchemy.*`, and `urllib3` / `httpx` / `httpcore` / `requests` below WARNING, are never stored (their lines carry full URLs).
- **Everything stored is redacted** (`redact()`): the exact token / key / secret / DB-password values from settings, plus `?key=` / `token=` / Bearer / Postgres-URL patterns. Still, never log a secret or a live measurement on purpose: logs are bookkeeping, not data.
- **Flushing:** the worker and CLIs flush from a daemon thread every `LOG_FLUSH_INTERVAL_S`, at once after an ERROR, and at exit. The API has no thread (Cloud Run cuts the CPU after the response): `app/api/request_log.py` flushes before each response returns. A failed insert (e.g. SQLite "database is locked") is printed to stderr, never re-logged, and its records go back in the buffer (what does not fit in `LOG_BUFFER_MAX` is counted in the "log buffer full" notice), and flushes pause for `RETRY_AFTER_FAILURE_S` (30 s; the request middleware skips its flush meanwhile, shutdown flushes don't wait).
- **Context:** `jobs.execute` sets `run_id` / `job` (context vars) for the run, and logs "job X started / finished"; `_per_phase` threads copy the context. The request middleware sets `request_id` (also the `X-Request-ID` header) and logs only 5xx / unhandled exceptions (with traceback) and requests slower than `LOG_SLOW_REQUEST_MS` (WARNING; `/growatt/live/*` only INFO, since there the wait is Growatt / Google refilling an expired live cache). `app.audit` logs failed logins (name only) and admin actions (job queued, user created/changed (field names only)/plants set, fleet module saved).
- **Volume:** the per-inverter line in `sync_history` is DEBUG; keep per-item lines at DEBUG and summaries at INFO.
- `/system/logs` (`?level=&source=&job=&run_id=&q=&since=&until=&before_id=&after_id=&limit=`, newest first; naive times = Bangkok; default window 24 h, a `run_id` alone = the whole run) and `/system/logs/summary` are in `services/system_logs.py`.

- Daily jobs fire only within 3 h after their slot.
- `services/jobs.py` holds the job bodies and the run log / lock (`sync_runs`). A tick runs its jobs one after another (queued runs first, then the due ones in schedule order); each is judged due and stamped `started_at` when it itself starts (`worker.tick`: the tick's `now` + whole seconds elapsed), so a run's `finished_at − started_at` is its own duration (before 26 Nov 2026 every job of a tick got the tick's start time, so a job after `history` looked as long as `history`).
- Keep SQLite write transactions short: the write lock is taken at a transaction's first write and held to its commit, and a waiting writer (API save, log flusher) sleeps between retries, so back-to-back transactions with only a few ms between them can starve it for seconds. Read and compute first, write last: `growatt_daily.compute_plant_day` (one commit per plant in `rules_today` / `rules_yesterday`) stages its rows under `no_autoflush` and deletes the old ones at the end (lock per `rules_today` 9.7 s → 0.3 s, worst wait of a write 4.4 s → 0.1 ms on a copy of the local DB, 26 Nov 2026).
- `GET /growatt/sync/status` and `POST /growatt/sync/{job}` cover the API side. **The API only queues a run** (`status = queued`); the worker starts it on its next tick (≤ 1 min). Never run jobs inside the API: on Cloud Run the CPU is cut after the response. A job that's already queued or running returns 409; a queued run nobody picks up within 2 h is marked failed.
- **Don't add `publish_today` runs.** An open day changes on every run, so each run rewrites about 250 Firestore documents (four a day: the three PWA checks and 19:30).

## Production (`APP_ENV=prod`)

- Startup refuses to run without `ADMIN_PASSWORD` (≥ 12 chars) or with the default / short `JWT_SECRET_KEY`.
- Only one admin is seeded, from `ADMIN_USERNAME` / `ADMIN_PASSWORD`. Changing the secret resets that admin's password. Demo accounts still on their demo password are disabled, and no demo plant data is created (`SEED_DEMO_DATA` overrides).
- Every data router requires a signed-in user (`main.py`); only `/auth/login` and `/health` are open. Files (CSV templates) are downloaded by the UI with `fetch` + token, not plain links.

## DB and migrations

- `DATABASE_URL` defaults to SQLite at `data/solar_fullstack.db`; Docker uses `postgresql+psycopg`. On SQLite `build_engine` sets WAL mode (readers and the writer no longer block each other; the file gets `-wal` / `-shm` companions, so copy all three or run `PRAGMA wal_checkpoint` before copying the DB) and a 30 s lock wait (`SQLITE_BUSY_TIMEOUT_S`).
- Startup (API and worker) calls `ensure_schema` (`db/session.py`): `create_all` plus `_ADDED_COLUMNS`, which adds new columns to existing tables, and `_DROPPED_INDEXES` / `_DROPPED_COLUMNS`, which drop retired ones (both lists are empty now). `_convert_string_readings` turns an old per-string `growatt_string_readings` table into `growatt_string_records` plus the view (once; advisory lock on Postgres). New tables and listed columns appear without Alembic. Still add a hand-written migration under `alembic/versions/` (chain `down_revision`, a fresh revision id: `uv run alembic -c backend/alembic.ini heads` must show one head) for Postgres.
- **String readings are one row per inverter record** (`growatt_string_records`: `strings` = JSON `[[string_no, mppt_no, voltage_v, current_a], …]`; Nov 2026, about a seventh of the per-string table, whose key and index were repeated for ~19 strings a record). `growatt_string_readings` is a **view** (`GrowattStringReading`, on `ViewBase`, created by a `Base.metadata` after-create hook) that unpacks it one row per string; read it as a table (filters on `device_sn` / `timestamp` use the records' primary key; `S.power_w` = `voltage_v * current_a`). Never write the view: `growatt_sync.store_string_rows` upserts per record and keeps strings already stored that a write leaves out; retention deletes records. Tests seed strings with `store_string_rows` too.
